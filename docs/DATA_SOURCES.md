# Data sources and provenance

The verified local run uses the 2025-04-14 Landsat 8 acquisition documented in [the heat workflow](HEAT_WORKFLOW.md). Its scene and model artifacts are kept in ignored local storage. The checkout has no time-stamped flood incident dataset or configured meteorological input.

| Input/output | Provenance class | Source and use | Limits |
|---|---|---|---|
| Default flood ward terrain | Synthetic | Seeded deterministic surface generated by `backend/app/gis/synthetic_ward.py`. It is anchored inside the Bellandur map bbox solely to co-locate the illustrative output. | Not observed Bellandur terrain. |
| Default flood roads | Synthetic | Seeded deterministic grid/arterials generated by `SyntheticWardProvider`. | Not OSM roads or real streets. |
| Default drainage tags/capacity | Synthetic / assumed | Seeded drain tags; pipe diameter and Manning roughness are configured assumptions. | Not municipal storm-drain assets or surveyed hydraulic capacity. |
| Default land cover / curve numbers | Synthetic / rule-based | Rule-based zones and curve numbers in `SyntheticWardProvider`. | No licensed land-cover raster is loaded. |
| Default critical facilities | Synthetic | Fixed placeholder hospital, fire station and shelter generated by the synthetic provider. | They are not real facilities. |
| Flood GNN training labels | Simulated | Generated by the simplified physics baseline in rainfall-intensity/duration sweeps; used to train the FloodGNN surrogate. | Surrogate agreement is not real-world predictive accuracy. No observed event validation is available. |
| Rainfall input | User scenario | Selected preset or user-entered intensity (mm/hr) and duration (min). | It is not an observation, nowcast or forecast. `/api/weather/nowcast` explicitly returns unavailable. |
| Optional terrain in `PILOT_MODE=real` | Remotely sourced | AWS Open Data Registry Terrain Tiles (`elevation-tiles-prod` Terrarium PNGs), unless a local GeoTIFF is supplied. The registry points to per-source attribution/terms. | This path was not run for the current MVP verification. It does not imply street-level flood validation. |
| Optional roads, waterways and facilities in `PILOT_MODE=real` | OSM sourced / inferred | OpenStreetMap queries through OSMnx/Overpass. Roads/facility tags are OSM data; a road's proximity to a mapped waterway is only an inferred drainage proxy. | OSM waterways are not verified municipal storm drains. This mode was not run for the current MVP verification. |
| Optional real-mode land use / curve number | Assumed | A flat CN=75 default is applied because no land-cover raster is configured. | Not observed land-use data. |
| Optional Landsat LST | Remotely sensed input + modelled output | One locally supplied Landsat 8/9 Collection 2 Level-2 scene, processed using bands `SR_B2`–`SR_B7`, `ST_B10`, `ST_EMIS`, `QA_PIXEL`. | No scene or model is bundled. Output is single-date LST, not air temperature or heatwave forecast. See [`HEAT_WORKFLOW.md`](HEAT_WORKFLOW.md). |
| Combined exposure | Derived overlay | Independent flood and heat outputs snapped to a fixed 30 m EPSG:32643 grid. | “Both elevated” is a transparent pair of thresholds, not a calibrated compound-risk probability. See [`GEO_ALIGNMENT.md`](GEO_ALIGNMENT.md). |
| Historical flood validation | Unavailable | No verified, time-stamped incident records with observation labels are included. The backtest endpoint returns 501. | BBMP flood-prone points, if later sourced, are spatial priors and are not event labels. |
| Heat-stress / heatwave advisory | Unavailable | No verified air-temperature and humidity time series or user-entered meteorological scenario is configured. | Landsat LST alone is not used to infer an advisory. |

## Source and licensing references

- [OpenStreetMap copyright and license](https://www.openstreetmap.org/copyright): OSM data are under ODbL and require attribution. The interactive map keeps the CARTO/OSM attribution control visible; if OSM-derived data are exported or redistributed, review the ODbL obligations for that use.
- [AWS Open Data Registry — Terrain Tiles](https://registry.opendata.aws/terrain-tiles/): AWS lists the source-specific attribution/terms at the [Tilezen attribution file](https://github.com/tilezen/joerd/blob/master/docs/attribution.md). Retain that source list with any exported DEM-derived result.
- [CARTO basemap terms](https://carto.com/legal/basemap-terms/) and [attribution guide](https://carto.com/attribution/): the current MapLibre style is served by CARTO and includes its required CARTO/OpenStreetMap credit. Basemap requests require internet access and remain subject to provider terms.
- [USGS Landsat Collection 2 Level-2 scale factors](https://www.usgs.gov/faqs/how-do-i-use-a-scale-factor-landsat-level-2-science-products), [QA_PIXEL flags](https://www.usgs.gov/landsat-missions/landsat-collection-2-quality-assessment-bands), and [surface-temperature caveats](https://www.usgs.gov/landsat-missions/landsat-collection-2-surface-temperature): these are the product docs followed by the heat workflow. Keep exact scene metadata and terms with any locally supplied product.
- For application-code licenses and attribution, see [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## Validation data gaps

- No verified, timestamped flood incidents or observations are used for model training or event-level evaluation.
- No meteorological time series is configured for a heatwave target or forecast horizon.
- The verified heat metrics apply only to a spatial holdout within one acquisition. A fresh checkout requires local scene and model files to display heat.
- The synthetic grid is positioned inside the Bellandur bbox for map comparison; this does not make its terrain, roads, drainage, or facilities local observations.

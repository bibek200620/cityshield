# Data sources and provenance

The verified local runs use one 2025-04-14 Bellandur Landsat 8 acquisition and 20 Landsat 8/9 city acquisitions documented in [the heat workflow](HEAT_WORKFLOW.md) and [Bengaluru evaluation](BENGALURU_EVALUATION.md). Scene and model artifacts are kept in ignored local storage. The checkout has no time-stamped flood incident dataset. The route weather view requests current plus three future hourly estimates from Open-Meteo when the provider is reachable.

## Source and licensing references

- [Open-Meteo Historical Weather API documentation](https://open-meteo.com/en/docs/historical-weather-api): ERA5-Land coverage, resolution, reanalysis provenance, archive parameters and temperature/RH fields. [Open-Meteo data license](https://open-meteo.com/en/license): CC BY 4.0; attribute the provider and identify transformations. Open-Meteo is the source of reanalysis/model estimates, not verified street observations.
- [Open-Meteo Forecast API documentation](https://open-meteo.com/en/docs): current and short-range weather fields. This live feed is separate from the offline ERA5-Land training archive.
| Historical flood validation | Unavailable | No evaluation-grade, time-stamped incident records with verified geometry, observed outcome and matched rainfall are included. The backtest endpoint returns 501. A coarse narrative reference is catalogued with explicit quality flags and is not used for scoring. | BBMP/OpenCity common flooding points are spatial priors and are not event labels. See [`FLOOD_EVENT_DATA.md`](FLOOD_EVENT_DATA.md) and the machine-readable manifest at `backend/app/ml/flood_event_sources.json`. |
| Heat-stress / heatwave advisory | Unavailable | No verified air-temperature and humidity time series or user-entered meteorological scenario is configured. | Landsat LST alone is not used to infer an advisory. |

## Validation data gaps

- No verified, timestamped flood incidents or observations are used for model training or event-level evaluation.
- No verified historical meteorological station-observation series is configured. An offline ERA5-Land model-derived next-day Tmax experiment exists, but it is not a heatwave-event target and its scores are not observed-data validation. The short-range Open-Meteo outlook is a separate forecast-model feed.
- The verified heat metrics apply only to a spatial holdout within one acquisition. A fresh checkout requires local scene and model files to display heat.
- No historical meteorological time series is configured for model training, heat-stress thresholds or a validated heatwave target/horizon. The short-range Open-Meteo outlook is a separate forecast-model feed.
- The Bellandur metrics apply to a spatial holdout within one acquisition. The city study reports a separate buffered spatial-block holdout across training acquisitions and a later-date holdout. A fresh checkout requires local scene/model files for Bellandur inference; city study scene inputs can be retrieved from the documented Planetary Computer collection when network access is available.
- The synthetic grid is positioned inside the Bellandur bbox for map comparison; this does not make its terrain, roads, drainage, or facilities local observations.

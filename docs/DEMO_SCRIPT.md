# Local research MVP walkthrough

## Start

Follow the local setup in the root README. Open <http://127.0.0.1:5173>. The app defaults to a deterministic synthetic flood network placed inside the Bellandur map extent. It is not observed Bellandur terrain, roads, drainage or facilities.

## Scenario and provenance

1. Open the scenario panel and choose a preset or set a user-entered intensity/duration.
2. Observe model-derived node depth, road classes and uncertainty. The result is generated by FloodGNN/MC Dropout with training targets from the simplified physics baseline.
3. Open analytics/provenance to see model mode/version, rainfall source, simulation timestamp, synthetic/simulated provenance and the unavailable observed-event validation status.

## Heat and combined layer

1. In the default checkout, the heat layer says unavailable because no Landsat scene or model artifact is shipped.
2. If a licensed scene and trained matching model have been added following [`HEAT_WORKFLOW.md`](HEAT_WORKFLOW.md), enable Land-surface temperature. The output is a single-scene LST pattern, not air temperature or a forecast.
3. Enable “Both hazards elevated” to see common-grid cells where the separate flood-depth and relative heat thresholds both pass. The API does not calculate compound probability.

## Limits to state

- This is a research simulation, not an official warning service or street-level verified depth source.
- No verified time-stamped flood events or live meteorological input are configured.
- If using route comparison, it is a simulation of assumed-speed route costs only. It is not navigation, traffic estimation, nor safe-road guidance.
- The CARTO basemap needs network access and displays CARTO/OpenStreetMap attribution.
